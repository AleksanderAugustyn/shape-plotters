# Handoff: engine v0.2 — interactive performance

**Date written:** 2026-07-03, for pickup 2026-07-04
**Symptom:** both plotters feel sluggish when dragging sliders under WSLg (user report after v0.1 gate).

## Diagnosis (measured, Agg backend, 2026-07-03)

| stage | beta | fos |
|---|---|---|
| `render.compute` (Fortran via ctypes) | 0.1 ms | 0.4 ms |
| full frame (`update()` + render) | ~990 ms | ~1180 ms |

The compiled libraries are ~1000× under budget; the cost is the v0.1 engine's update loop:
1. `update()` calls `ax.clear()` and rebuilds every artist (legends, grids, ticks, stats text, equal-aspect) on every slider motion event. Legend/text layout is among matplotlib's slowest paths.
2. `draw_idle()` re-rasterizes the whole figure — 30 axes (each slider row = slider + 2 nudge buttons), not just the 3–4 data panels.

Benchmark gotcha: under Agg, `draw_idle()` draws immediately (no event loop), so `update()` timings already include one full draw. Reproduce with:

```python
# MPLBACKEND=Agg, repo root on sys.path
import time
from src.core.engine import ShapePlotterApp
from src.renders.beta import BetaRender
app = ShapePlotterApp(BetaRender())
params = {k: r.slider.val for k, r in app.rows.items()}; params["beta2"] = 1.3
t0 = time.perf_counter()
for _ in range(10): app.update(); app.fig.canvas.draw()
print((time.perf_counter() - t0) / 10 * 1000, "ms/frame")
```

## Fix plan (touch `src/core/engine.py` only; renders and contract unchanged)

1. **Persistent artists**, created once at figure build: `r_line`, `dr_line` (ax_radius); `shape_upper`, `shape_lower`, `neck_line` (ax_shape — make the neck a `Line2D` with two points instead of `vlines`, so it can be `set_data`'d/hidden); `extra_rho`, `extra_drho` (ax_extra); one stats `Text` artist; invalid banner stays as the ax_shape title.
2. `update()`: `set_data` on lines; toggle visibility for the neck line; change colors/alpha only when validity flips (track previous state); `stats_text.set_text(...)`; `ax.relim()` + `ax.autoscale_view()` on data panels; one `draw_idle()`.
3. Legends, axis labels, equal-aspect: set once at build; rebuild legend texts only on the unit toggle (rare event), e.g. `legend.get_texts()[i].set_text(...)`.
4. Set `slider.drawon = False` on all sliders (verify the attribute in mpl 3.11) — the engine's update draws; avoids `Slider.set_val`'s own `draw_idle`. Same check for CheckButtons/Button if they have one.
5. **Stage 2, only if still sluggish interactively:** per-panel blitting (capture backgrounds, redraw animated artists only, recapture on resize/limit change/unit toggle). Don't build this preemptively — measure stage 1–4 on TkAgg first.

## Known uncertainties (from the diagnosis session)

- Speedup magnitude on TkAgg/WSLg is extrapolated from Agg; Slider internals may still force wider redraws. Measure interactively before/after; escalate to blitting if needed.
- If even blitting isn't enough and ShapePlotters becomes a daily tool: the engine/render split was designed so a native-Qt shell (Qt sliders + embedded mpl canvas) can replace `ShapePlotterApp` without touching renders. That's a v0.3 decision, not this handoff.
