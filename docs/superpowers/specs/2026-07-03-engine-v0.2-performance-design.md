# Engine v0.2: interactive performance — design

**Date:** 2026-07-03
**Source:** `docs/handoffs/2026-07-04-engine-v0.2-performance-handoff.md`
**Goal:** slider-drag responsiveness on par with the previous pure-Python plotters
(`../ShapePlotter/`, `../ShapePlotterFoSFitter/`). Not maximum performance — parity.

## Problem

Measured under Agg (2026-07-03): `render.compute` costs 0.1 ms (beta) / 0.4 ms (fos),
but a full frame costs ~990 / ~1180 ms. The v0.1 engine clears and rebuilds every
artist (legends, grids, labels, stats text) on each slider event. Legend/text layout
is among matplotlib's slowest paths. Both old plotters avoided this with persistent
artists mutated via `set_data` — that pattern is the parity fix.

## Approach (chosen: persistent artists)

Considered:

- **A. Persistent artists** (handoff stages 1–4) — build every artist once; `update()`
  only mutates data/text/visibility. Proven by both old plotters. **Chosen.**
- **B. Blitting-first** — fastest possible, but adds background-recapture bookkeeping
  (resize, limit change, unit toggle) the old plotters never needed. Deferred:
  contingency only, gated on interactive TkAgg/WSLg measurement after A.
- **C. Event debouncing** — fewer frames, but each frame still costs ~1 s. Rejected.

Scope: `src/core/engine.py` only (plus tests and docs). Renders and the
`ShapeResult` contract unchanged.

## Design

### Artist architecture — build once, mutate forever

New `_build_artists()` step after `_build_figure()`. Every artist is created once with
placeholder data and stored as an attribute. `update()` never creates or removes artists.

| Axes | Persistent artists | Set once at build |
|---|---|---|
| `ax_radius` | `r_line` (solid), `dr_line` (dotted) | xlim (0, π), xlabel, legend, grid |
| `ax_shape` | `shape_upper`, `shape_lower`, `neck_line`, 2 scission band rectangles | equal-datalim aspect, xlabel/ylabel, grid |
| `ax_extra` (fos) | `extra_rho`, `extra_drho` | xlabel, legend, grid |
| `ax_stats` | `stats_text` (one `Text`) | position, monospace font |

- `neck_line`: a 2-point `Line2D` replacing `ax.vlines` (a `LineCollection` can't be
  `set_data`'d cleanly; a 2-point line is visually identical).
- Invalid banner stays as the `ax_shape` title; `set_title` called only when the
  string actually changes.
- Legends built once from the persistent lines; the unit toggle re-texts entries in
  place via `legend.get_texts()[i].set_text(...)`.

### Scission bands (new feature, engine-owned)

Two light shaded horizontal bands (`axhspan`) on `ax_shape`: ρ ∈ [1.2, 1.5] fm and its
mirror ρ ∈ [−1.5, −1.2] fm — WMMM's scission bands. Valid for both renders because the
display convention R0 = 1.16 fm equals WMMM's geometric R₀ (see handoff / FORD.md).

- Toggle: new entry in the engine `CheckButtons` group (alongside the fm/R0 toggle),
  labeled e.g. "scission bands", default **off**.
- In R0 display units the edges become 1.2/scale and 1.5/scale; rectangles are
  repositioned via `set_xy`/height updates only on unit toggle or Z/N change.
- Hidden bands cost nothing per frame (`set_visible(False)`).

### Hot path — `update()` per slider motion

1. `render.compute(params, toggles)` (~0.1–0.4 ms, unchanged).
2. `set_data` on data lines: `r_line`, `dr_line`, `shape_upper`, `shape_lower`,
   and `extra_rho`/`extra_drho` when present.
3. Neck: `set_data` + `set_visible(True)` if `result.neck` else `set_visible(False)`.
4. Validity styling: track `self._last_ok`; only on a flip, set color/alpha on the data
   lines (valid palette ↔ grey `0.55` / alpha 0.45).
5. `stats_text.set_text(...)` — same content as v0.1, no `ax.clear()`.
6. `relim()` + `autoscale_view()` on data panels (works with equal-datalim aspect).
7. One `fig.canvas.draw_idle()`.

### Rare events (each ends by calling `update()`)

- **Unit toggle**: re-text legend entries and axis labels in place; reposition
  scission bands.
- **Z/N change**: scale changes in fm mode; reposition scission bands.
- **Scission toggle**: `set_visible` on the two rectangles.
- **Reset**: unchanged — 8 chained `set_val` calls are fine once frames are cheap.

### Widget draw suppression

`drawon = False` on all `Slider`s, the `CheckButtons`, and the nudge/reset/save
`Button`s. `drawon` lives on the `AxesWidget` base class — verify in mpl 3.11 before
relying on it (same caution as the version-guarded `IntTextBox` resize workaround,
which stays). The engine's `update()` issues the single authoritative `draw_idle()`.

### Error handling

Invalid shapes (result.ok false) follow the same path as v0.1: grey styling, banner
in the title, stats prefixed with the status. No new failure modes are introduced —
the artist set is fixed, so there is no partial-rebuild state to corrupt.

## Testing

- **Existing 31 tests green.** `test_engine.py` touch-ups only where clear-and-replot
  side effects were assumed; current assertions (`get_xlabel` after unit toggle,
  `get_title` banner) survive as written.
- **Perf guard (new, pytest, Agg):** one warm-up frame (font cache/first layout), then
  mean of 10 × (`update()` + `canvas.draw()`); assert mean < 300 ms/frame for both
  renders. Current baseline ~990/1180 ms; expected result well under 150 ms — the
  ceiling is generous to absorb WSL/CI jitter.
- **Scission bands (new):** artists exist after build; toggle flips visibility;
  fm→R0 toggle rescales band edges.
- **Neck visibility (new):** neck line hides when the result has no neck and returns
  when it does.

## Acceptance

- All tests green (existing + new).
- Headless benchmark drops by roughly an order of magnitude.
- Real gate: slider drag under WSLg feels responsive — user verdict. If it still feels
  sluggish, escalate to per-panel blitting (stage 2 of the handoff) as a separate task;
  do not build it preemptively.

## Compiled-library candidates (tracking)

Create `docs/compiled-lib-candidates.md`, a living list of Python-side work that could
move into the compiled parameterization libraries. Seed entries:

| Candidate | Current Python cost | Fortran API needed |
|---|---|---|
| Volume / surface / z_cm (stats) | 3 quadratures over 721 pts per frame (µs; `src/core/quadrature.py`, display-grid accuracy) | exact integrals returned by the shape library |
| dR/dθ display curve | `np.gradient` over 721 pts (µs; finite-difference accuracy) | analytic derivative on the display grid |
| (reference) `render.compute` | already compiled: 0.1 ms beta / 0.4 ms fos | — |

None of these are performance problems today; entries exist for accuracy/parity and so
future sessions keep the list current.

## Known uncertainties (carried from handoff)

- Speedup on TkAgg/WSLg is extrapolated from Agg; Slider internals may force wider
  redraws. Measure interactively before/after; blitting is the fallback.
- If even blitting is insufficient and this becomes a daily tool, a native-Qt shell
  replacing `ShapePlotterApp` (renders untouched) is the v0.3 option — out of scope.
